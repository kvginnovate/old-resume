# 13. AI Memory Systems — SuperMemory & claude-mem (Avoiding Context Loss)

**Target:** Principal Software Engineer V — The Standard (IBTE)
**Duration:** 60-70 seconds

---

## Question

**Interviewer:** "You mentioned configuring MCP servers and building AI agents. Agents lose context across sessions — how did you handle that? How do you keep the agent from forgetting what it did last week?"

---

## Answer

The agents I built in Kiro had a real problem. Every session started fresh. The agent would fix a defect, and the next session didn't remember what it did, what the team conventions were, or which services were involved. Context loss was killing the reliability of the automation.

So I built the knowledge around the agents in three layers. First, a project knowledgebase in markdown that all developers use, covering architecture decisions, service ownership, and conventions. The defect fixing skill searches that knowledgebase on demand before it triages, so the agent works with the same ground truth the developers do. Second, SuperMemory MCP, which gives the agents a shared persistent memory store, so anything learned in one session is available in any other session and across tools. And third, claude mem, which runs as a plugin inside the development environment, captures everything the agent does during a session, compresses it with AI into summaries, and injects the relevant context back into future sessions.

The key design principle was progressive disclosure. Instead of dumping the whole history into the prompt, which would blow up token usage, claude mem exposes search tools that work in layers. First a compact index, then a timeline around interesting results, then full details only for the observations that actually matter. That is roughly ten times token savings compared to loading everything.

The result was that defect triage became consistent. The agent knew the project history, the conventions, and the patterns, because the memory was there. I stopped re explaining context, and the agents started carrying it themselves.

- **Measurable:** "~10x token savings" — you quantify, you don't hand-wave

## Product Details (know these cold)

### Project Knowledgebase (.md) — Layer 1
- Markdown knowledgebase covering architecture decisions, service ownership, conventions — used by all developers
- The defect-fixing skill **searches it on demand** (retrieval, not injection) before triaging, so the agent works from the same ground truth as the team
- This is the institutional-knowledge layer — what a new developer gets on day one, now available to agents

### SuperMemory MCP — Layer 2
- Universal memory layer for AI agents over MCP — one shared memory store any MCP-compatible AI can read/write
- Hosted on Cloudflare (durable objects); vector semantic search (FAISS/SQLite for self-host); SSE transport
- Setup: `npx -y install-mcp@latest https://mcp.supermemory.ai/mcp --client <cursor/windsurf/vscode/...>`
- [github.com/supermemoryai/supermemory-mcp](https://github.com/supermemoryai/supermemory-mcp)

### claude-mem (`thedotmack/claude-mem`)
- Persistent memory compression for coding agents — captures sessions, compresses with AI, injects context into future sessions
- 89K+ GitHub stars, Apache 2.0, by Alex Newman
- **Install is `npx claude-mem install`** or `/plugin marketplace add thedotmack/claude-mem` + `/plugin install claude-mem`. Note: `npm install -g claude-mem` installs the SDK/library only — it does NOT register the plugin hooks or worker service
- Architecture: 5 lifecycle hooks (SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd) → Bun-managed local worker service with HTTP API and web viewer → SQLite storage + Chroma vector DB
- MCP tools are the search layer only: `search` (compact index ~50-100 tokens/result) → `timeline` (chronological context) → `get_observations` (full details only for filtered IDs ~500-1,000 tokens/result)
- Works with Claude Code, OpenClaw, Codex, Gemini, Copilot, OpenCode
- Privacy: `<private>` tags exclude sensitive content from storage; cloud sync optional, local-first by default
- [github.com/thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)

## Follow-Up Questions

- **"What's the difference between the knowledgebase and the memory systems?"** — The knowledgebase is institutional truth: architecture decisions, service ownership, conventions, written in markdown and shared with all developers. The agent searches it on demand before triaging. The memory systems are machine recall: SuperMemory shares knowledge across sessions and tools, claude-mem captures and compresses what the agent did. One is the team's documented knowledge, the other is the agent's own memory.
- **"What's the difference between SuperMemory and claude-mem?"** — SuperMemory solves cross-agent memory: one shared store every AI can read and write, so knowledge isn't trapped in one chat. claude-mem solves session memory inside a coding environment: it captures what the agent did, compresses it, and injects the relevant part back. One is a shared hub, the other is a session recorder with smart retrieval.
- **"What about security and privacy of agent memory?"** — Memory stays local by default with claude-mem, and cloud sync is opt in. There's a private tag mechanism to exclude sensitive content. SuperMemory can be self hosted. Same principle as any data layer: know what is stored, where, and who can read it.
- **"How did you measure that it helped?"** — Token usage per task dropped because we retrieved only what was relevant. And the consistency of fixes improved, because the agent carried project conventions across sessions instead of rediscovering them each time.
