# 15. Enterprise AI Governance — The Agent Control Plane Story

**Target:** Principal Software Engineer V — The Standard (IBTE)
**Type:** Differentiator story — merges existing work under the 2026 enterprise frame

---

## The Question This Answers

**Interviewer:** "You've built agents that write code, fix defects, and provision infrastructure. In an insurance company, how do we trust that? What stops an agent from doing something wrong — or worse, something we can't audit?"

---

## Answer

> "The question isn't whether agents can do the work — they can. The question is whether you can govern, audit, and control them. That's the part I treat as the architecture, not the afterthought.
>
> Every agent I've built runs through a control plane with the same three rules. Scoped permissions — the agent can only do what its task requires. Audit trails — every agent action is logged with identity, timestamp, and parameters. Human approval gates — agents can propose, but humans decide the irreversible things.
>
> Concretely: the GitLab MCP server can read code and create pull requests, but it can never merge. The Dynatrace MCP server can read traces, but it can never modify monitoring. The provisioning MCP servers can create resources, but never delete billing-critical ones. When security asked 'what stops an agent from deleting production data?' I had the answer ready, because I designed for that question before it was asked.
>
> The same discipline applies to what the agent knows. Agents at enterprise scale don't fail from context loss — they fail from stale or wrong context. So I built a three layer memory model: a curated markdown knowledgebase as ground truth that the agent retrieves, not guesses; shared memory across sessions; and session compression so the agent carries only what's relevant. Retrieval over context stuffing — the agent pulls the right knowledge just in time.
>
> And I validate the output, not just the process. Tests must pass against old and new code. Security rescan rejects any fix that introduces a new vulnerability. Agents get a limited number of iterations before escalating to a human. The output is judged against a contract, not vibes.
>
> Insurance is the textbook case for this. Claims and underwriting are regulated, high stakes decisions. You can't have a black box approving a claim. The governance model I built — scoped permissions, audit trails, approval gates, spec as contract — is exactly what a regulated AI program needs. That's why this role and this industry feel like the right fit for what I've been building."

## Follow-Up Questions

- **"What stops an agent from making a destructive change?"** — Three layers. MCP permissions: agents are read-only for monitoring, write-PR-never-merge for GitLab. Playbook gates: agents stop and escalate before destructive operations. Code review: every AI-generated PR needs human approval. Defense in depth, same as any security architecture.
- **"How do you know the AI didn't introduce a bug?"** — Tests must pass against old and new code. Security rescan catches fixes that introduce vulnerabilities. Human reviews every AI-generated test assertion. And a hard iteration limit — three tries, then escalate. The agent can't tunnel on a bad fix.
- **"How is this different from regular security or compliance?"** — Same principles, different surface. Traditional security governs human access; agent governance governs machine action. The difference is scale and speed — an agent acts in seconds and across many systems, so the audit trail has to be machine-readable and the permissions machine-scoped. The model is the same, the enforcement has to be automated.
- **"How does this map to insurance regulation?"** — Regulated AI needs three things: model inventory (what AI exists and what it does), risk assessment (what it can touch), and auditable logging (what it actually did). My model maps directly: every agent skill is a model inventory entry, scoped permissions are the risk assessment, and the audit trail is the logging. The framework transfers, the domain specifics change.
