## Question This Answers

## Answer

> We've moved away from what people call vibe coding — informal, iterative prompting where you ask an AI to write code and hope it's right. We use a structured methodology called AI DLC, the AI Driven Development Life Cycle, with Kiro as the execution engine. Kiro is AWS's agentic IDE.
>
> The core principle is plan before you code. Spec driven development. Instead of asking the AI to write code immediately, we write the specification first. Kiro generates a master markdown file with the requirements and the design before a single line of code is written. That gives the agent the complete context it needs, which is what avoids bugs in the first place.
>
> The lifecycle has three phases. Inception, where the AI analyzes the prompt or the Figma design and generates user stories and acceptance criteria, and the team reviews them. Construction, where the AI proposes the architecture, sequence diagrams, and a task list, and then agents execute the tasks one by one, writing both the production code and the tests. And Operations, where the accumulated context is converted into infrastructure as code and deployment pipelines.
>
> Three features make it work. Steering files, which give the agent our coding conventions and guardrails. Hooks, which run automated validations when we save or commit, so the code continuously aligns with the spec. And MCP servers, which connect the agents to our real tools, APIs, and databases so they work with live data, not assumptions.
>
> The result is that AI stops being a code generator and becomes part of a governed engineering process. Same discipline as a traditional SDLC, with the speed of automation.

## The AI-DLC Framework (The Process) — Verified

AI-DLC (AI-Driven Development Life Cycle) is AWS's published methodology for agentic software development. It reimagines the software cycle into three automated, human-vetted phases:

| Phase | What Happens | Human Role |
|---|---|---|
| **1. Inception** (What to build) | AI performs workspace detection, analyzes natural language prompts or Figma designs, generates structured user stories and acceptance criteria | Team reviews via "Mob Elaboration" |
| **2. Construction** (How to build) | AI proposes logical system architectures, sequence diagrams, domain models, then a discrete implementation task list | Team reviews and approves architecture and tasks |
| **3. Operations** (How to run) | Accumulated context auto-converts into infrastructure-as-code and deployment pipelines | Human oversight and approvals |

Sources: [AWS DevOps blog — AI-DLC](https://aws.amazon.com/blogs/devops/ai-driven-development-life-cycle/), [specs.md — What is AI-DLC](https://specs.md/methodology/what-is-ai-dlc)

## Kiro — The Execution Engine — Verified

Kiro is AWS's agentic IDE (VS Code fork, IDE + CLI), released public preview July 2025, GA later that year. It embeds AI across the whole lifecycle:

| Feature | What It Does |
|---|---|
| **Specs** | Generates a master markdown file (e.g., AGENTS.md) with requirements and designs BEFORE code is written — the AI's complete context |
| **Steering** | Project guidance files that supply the agent coding conventions, guardrails, and architectural guidelines |
| **Autopilot** | Autonomous execution — agents run the task list, writing production code and tests |
| **Hooks** | Automated triggers run predefined agent validations on save/commit, keeping code aligned with the spec |
| **MCP** | Integrates external tools, APIs, and databases so agents pull real-time data into the loop |

Sources: [kiro.dev](https://kiro.dev/), [InfoQ — Amazon Introduces Kiro](https://www.infoq.com/news/2025/08/aws-kiro-spec-driven-agent/), [GitHub kirodotdev/Kiro](https://github.com/kirodotdev/Kiro), [Setting up Kiro for AI-native SDLC](https://dev.to/dvddpl/setting-up-kiro-for-your-ai-native-sdlc-578c)

## The Step-by-Step Workflow in Practice

```
[ Natural Prompt / Figma ]
          │
          ▼
┌────────────────────────────────────────────────────────┐
│ 1. INCEPTION (Kiro generates Specs & User Stories)     │  ◄── Team reviews
└─────────────────────────┬──────────────────────────────┘      & approves
                          │
                          ▼
┌────────────────────────────────────────────────────────┐
│ 2. DESIGN (Kiro builds Architecture & Task Lists)       │  ◄── Team reviews
└─────────────────────────┬──────────────────────────────┘      & approves
                          │
                          ▼
┌────────────────────────────────────────────────────────┐
│ 3. CONSTRUCTION (Kiro Agents auto-generate Code/Tests) │
└─────────────────────────┬──────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────┐
│ 4. OPERATIONS (Hooks validate code / IaC generated)    │
└────────────────────────────────────────────────────────┘
```

1. **Define Intent** — feed a product brief or UI design into Kiro
2. **Generate Spec** — Kiro breaks the prompt into user stories, acceptance criteria, structured designs, implementation tasks
3. **Approve Design** — Kiro maps technical blueprints; you review and adjust tasks or architecture
4. **Execute & Test** — agents execute tasks one by one, writing production code AND tests
5. **Verify via Hooks** — hooks trigger validations on file save to ensure spec compliance

## Follow-Up Questions

- **"How is this different from just using Cursor or Copilot?"** — Those optimize for speed — write code fast. Kiro optimizes for governance — plan, then build, then validate. The spec is a first-class artifact the team reviews before code exists. That's the difference between an assistant and an engineering process.
- **"Doesn't the spec phase slow you down?"** — It feels slower for the first feature, but the payoff is in maintenance. Bugs caught at spec time cost minutes; bugs caught in production cost days. The hooks validate continuously, so the spec isn't a document that goes stale — it's a contract the code is checked against on every save.
- **"What's your role when agents do the coding?"** — I own the process. I define the steering files and guardrails, review the specs and architectures, decide what agents can do autonomously and what needs human approval, and review the output. The agents do the execution; I do the engineering judgment.
- **"Is Kiro an AWS product? Why AWS?"** — Yes, Kiro is AWS's agentic IDE. The value isn't the vendor — it's the spec-driven methodology, which is vendor neutral. We chose Kiro because it was the first tool that made spec driven development a first-class workflow instead of a manual discipline.
