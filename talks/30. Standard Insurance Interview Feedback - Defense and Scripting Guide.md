## 2. Deep-Dive Component Architecture (STB Health & My Dish App)

### ❓ Possible Interview Question:
*"Walk me through a complex component you architected. Explain the internal mechanics, failure modes, and data flow."*

### 💬 Staff-Level Response Script (STB Health Diagnostic & Telemetry Gateway):
> "I'll deep-dive into the **STB Health Diagnostic & Telemetry Gateway** component of My Dish App, serving 10M+ subscriber Set-Top Boxes.
>
> ### High-Level Architecture & Traffic Flow
> 1. **Ingress & Security Gate (DMZ):**
>    * Requests arrive at a public DMZ API Gateway.
>    * Authenticated via **JWT token validation (Okta + AWS Cognito)** with automated certificate rotation.
>    * Ingress rate limiting enforced via **Resilience4j Bulkhead and RateLimiter** to absorb traffic spikes from technician field tools.
>
> 2. **Caching Strategy (GemFire):**
>    * Read-heavy diagnostic baseline queries hit **Pivotal GemFire distributed cache** with read-through configuration, achieving sub-10ms response times and insulating PostgreSQL.
>
> 3. **Asynchronous Telemetry Ingestion (Kafka / Queue):**
>    * Heavy telemetry payloads bypass synchronous DB writes.
>    * The gateway validates OpenAPI payloads, enriches metadata, and streams events to a messaging topic for decoupled downstream ingestion.
>
> 4. **Database Mechanics & Tuning:**
>    * Managed via **Spring Boot 3 + PostgreSQL** with schema migrations versioned in **Liquibase**.
>    * HikariCP connection pool tuned specifically for containerized pod limits (`maximumPoolSize=30`, `minimumIdle=10`, `connectionTimeout=250ms`).
>
> 5. **Observability & Fault Tolerance:**
>    * Distributed tracing configured with **Dynatrace APM**.
>    * Fallback mechanics configured using Resilience4j Circuit Breakers to return cached baseline status if downstream legacy systems degrade."

## 4. Confluent Event-Driven Architecture (Kafka Knowledge)

### ❓ Possible Interview Question:
*"How do you handle messaging and Event-Driven Architecture (EDA), particularly with Confluent Kafka?"*

### 💬 Staff-Level Response Script:
> "While my production architecture at Dish combined RabbitMQ, enterprise REST, and messaging queues, the core principles of Event-Driven Architecture remain constant. I am well-versed in Confluent Kafka patterns for enterprise integration:
>
> 1. **Partitioning & Ordering Guarantees:** Assigning event partition keys (e.g., `subscriber_id` or `claim_id`) to ensure strict in-order message delivery per entity while scaling throughput horizontally across partitions.
> 2. **Schema Governance (Confluent Schema Registry):** Utilizing Avro schemas registered with the Schema Registry to enforce contract compatibility (`BACKWARD` / `FULL` mode), allowing producers to evolve data contracts without breaking downstream consumers.
> 3. **Consumer Offset Management & Rebalancing:** Using explicit manual commit strategies (`MANUAL_IMMEDIATE` in Spring Kafka) to avoid message loss during pod restarts or rebalances.
> 4. **Resilience & Dead Letter Topics (DLT):** Configuring exponential backoff retry templates. Unprocessable/corrupt messages route to a Dead Letter Topic (DLT) with diagnostic stack traces in headers to prevent poison-pill blocking."

## 5. Communication & Answer Structure Framework

### 💡 The Senior/Staff Communication Standard (BLUF + STAR)

When answering architectural or situational questions, structure responses using this 4-step framework:

```
[1. BLUF] Bottom Line Up Front (1 sentence summary answer)
[2. SIGNPOSTING] "I'll break this down into 3 areas: X, Y, and Z..."
[3. DEEP TECH DETAILS] Give exact stack names, patterns, and mechanics
[4. METRIC IMPACT] End with quantified business or performance metrics
```
